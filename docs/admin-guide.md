# 画面と管理操作

## 公開ポータル

ルートの`index.html`には公開Projectの一覧と、ユーザー登録・ログインへの導線があります。公開設定されたProjectのみ表示し、各フロントエンドの`og:image`と`og:description`をリストに使用します。取得できない画像は非表示にします。`api/project-preview.php?app=...`は公開Projectのメタデータだけを取得し、結果を6時間キャッシュします。取得先は公開IPのHTTP/HTTPS標準ポートに限定します。

## プロジェクト管理

「プロジェクト設定」の「SPAのサーバーレンダリング支援」は初期状態で閉じています。有効化・パス・タイトル・共通説明・OGP画像を設定し、上部の「設定を保存」で反映します。公開URLとポータル公開が必要です。Cloudflare WorkersとSPA側のURL対応は別途設定します。既存DBには`migrations/013_project_page_rendering.sql`を適用してください。詳しくは[サーバーレンダリング支援](server-rendering.md)を参照してください。

`admin/index.html`を開き、独立したログイン画面から有効なユーザーのHTTP Basic認証情報でログインします。認証成功後にだけコンソールを表示し、ログアウトするとパスワードと画面上の管理データを破棄してログイン画面へ戻ります。`admin`はProject一覧、カラム定義、Activity表、ユーザー管理を利用できます。一般ユーザーにもProject一覧と作成ボタンを表示します。作成したProjectは直後から設定・Activity編集ができ、`editor`は割り当て済みActivityを編集可能、`viewer`は閲覧のみです。Activity Schemaの`type`に応じて`text`、`textarea`、`number`、`date`、`select`、`checkbox`、`url`、`image`の編集欄を生成します。MIT LicenseのTabulator 6.5.2を採用し、CSS/JavaScriptはバージョンとSRIハッシュを固定してUNPKGから読み込みます。

管理操作の導線は「ポータル → ログイン → プロジェクト一覧 → プロジェクト詳細 → 各管理画面」です。ログイン直後はポータルの一覧（`/#projects`）へ移動します。従来の`admin/?view=projects`も同じ一覧へ移動し、管理側に独立した一覧画面はありません。未ログイン時は公開プロジェクトのみ、ログイン中は権限のある非公開プロジェクトも表示し、各行の「プロジェクト詳細」から「プロジェクト設定」「投稿データ管理」「ユーザー管理」「削除済みデータ管理」を開きます。操作メニューは既存の権限に応じて表示し、共通ヘッダーの「プロジェクト一覧」と、公開・管理画面で共通の「ポータル › プロジェクト一覧 › プロジェクト名 › 操作画面」のパンくずから戻れます。一覧リンクはログイン状態によらずポータルへ進みます。プロジェクト作成と削除済みデータ管理の入口もポータルに表示します。プロジェクト設定の「ユーザー管理」リンクから参加権限を変更できます。「プロジェクトを削除」は復元可能な削除です。全体管理者が「削除済みデータ管理」から復元または完全削除できます。削除済みデータ管理は管理者専用で、従来どおり全体の削除済みプロジェクトを扱います。プロジェクトが0件のときも一覧に復元画面への入口を表示します。

「プロジェクト設定」の「メンバー募集中」は初期状態でオフです。公開・有効・募集中のプロジェクトでは、詳細に未参加ユーザー向けの「参加する」を表示します。未ログイン時は参加先付きの登録画面へ進み、ログイン中は本人を`contributor`として参加登録します。既存の参加権限は変更しません。募集停止後も既存メンバーの参加状態は維持します。既存DBには`migrations/012_project_recruitment.sql`を適用してください。

管理画面のフォーム、ボタン、表、カードなどはBootstrap 5.3.3を使用します。BootstrapのCSSはバージョンを固定してjsDelivrから読み込み、モーダル用のJavaScriptは`admin/vendor/bootstrap.bundle.min.js`を同一オリジンから読み込みます。表のスクロールやTabulator固有の表示などには`admin/admin.css`を使用します。操作結果やエラーはBootstrapの通知モーダルで表示しますが、ログイン成功時とProject・Activity・ユーザー一覧の通常の読み込み完了時には開きません。

英語表示は`/en/admin/`です。管理画面の処理は`admin/admin.js`で共通化し、動的な表示文言は翻訳キーを通して`admin/ja.json`と`admin/en.json`で管理します。英語版の静的な画面文言は`en/admin/index.html`にあります。プロジェクト名やカラムの表示名など、保存されたデータは翻訳せず登録された文字列を表示します。

- Projectの作成、表示名編集、削除（`app_key`は変更不可）
- Tabulatorによるカラムの追加、削除、ドラッグ順序変更、入力型・必須・表示・編集可否・幅のセル編集（選択肢は`select` / `checkbox`型のみ編集可能）
- プロジェクト一覧での対象切替、全列検索、Tabulatorの列別絞り込み（空欄は`""`を入力。通常の検索語も`"公園"`のように引用符で囲めます）・並び替え・列幅変更
- 画面内の利用可能領域へ表を自動追従し、ページではなく表内のスクロールだけで全行・全列を移動
- セル範囲選択、Tab / Shift+Tab・矢印キー移動、複数セルのコピー&ペースト
- 行追加・削除を含むローカル変更の一括保存と、未保存セル・行の表示
- 未保存変更がある状態での画面移動・再読込・離脱警告
- 一括保存失敗時のDBロールバックと画面上の編集内容保持
- JSON/CSV export
- JSON importのdry-run確認、CSVヘッダーからのSchema候補確認とimport
- URLの`view` / `app`による表示状態復元
- ユーザー一覧、検索、status・メール確認・role・Projectによる絞り込みとpagination
- ユーザー詳細、`active` / `disabled`切替、`user` / `admin`変更、Project role設定
- メールによるユーザー招待、または管理者が初期パスワードを設定するメールなしユーザー追加
- 確認メール再送、パスワード再設定メール送信（メール登録ユーザーのみ）
- ユーザー詳細画面からの管理者による直接パスワード再設定（状態・role・Project権限の保存とは独立）
- Activity投稿数・最近の投稿表示（作成者・最終更新者をActivityへ記録）

管理画面は認証APIと同じオリジンへ配置する想定です。一般公開せず、Webサーバー側のアクセス制御も併用してください。

管理画面のログイン成功後は、HttpOnly・SameSite=StrictのセッションCookie（有効期限なし）で認証を維持します。再読み込みや同じオリジンの別タブでも復元し、平文パスワードをlocalStorage/sessionStorageには保存しません。通常はブラウザ終了でCookieが破棄されますが、ブラウザのセッション復元機能で復元される場合があるため、確実に終了する場合はログアウトしてください。サーバーのセッション保存領域は書き込み可能にする必要があり、24時間以上未使用のセッションは削除対象になります。アカウント無効化・パスワード変更でも既存セッションを無効化します。

セッションAPIと各操作の権限は[APIリファレンス](api-reference.md#認証と権限)を参照してください。

## ユーザー登録

確認メールが届かない場合は、ブラウザを閉じた後も `/register.html` の「確認メールが届かない方」から登録したメールアドレスを入力して再送できます。同じメールアドレスで再登録を試した場合も再送欄を表示します。未確認のアカウントを作り直したり、パスワードを変更したりする必要はありません。

メールの確認リンクは確認画面を開き、本人が確認ボタンを押すと完了メッセージを表示します。旧設定の `/auth/verify.php?token=...` をブラウザで開いた場合も確認画面へ移動し、画面を開いただけではトークンを消費しません。APIとしてJSONを要求する場合は従来の応答を返します。

公開画面は `/register.html` です。`/admin/` のログイン画面から移動できます。メールに届く `/verify-email.html?token=...` を開き、確認ボタンを押すと登録が有効になります。確認前はログインできません。登録直後のアカウント権限は `user`（一般ユーザー）です。メール確認後に管理画面へログインし、自分のProjectを作成できます。作成したProjectには `project_admin` が付与され、設定・Activityの管理ができます。登録時に参加した他のProjectの権限は `contributor`（投稿者）のままで、アプリからの投稿・編集のみ可能です。他人のProjectの設定や管理画面の表、全体のユーザー管理は利用できません。既存アカウントの権限は自動変更しません。全体ロールは `user` と `admin` のみで、`contributor` はプロジェクトごとの投稿者権限として使います。

登録画面のURLを `/register.html?app_key=playgrounds` のようにすると、そのProjectが参加先として初期選択されます。登録画面の「参加プロジェクト」で別の公開Projectを選ぶこともできます。登録時に選択したProjectの `contributor`（投稿者）権限を付与します。他のProjectではその `app_key` を指定してください。対象はポータル公開（`frontend_public=true`）・有効・未削除のProjectです。非公開Projectへの参加は管理者が割り当てます。URL引数がない場合は、画面で参加Projectを選択できます。初期値の「後で決める・自分でつくる」を選ぶと既存Projectへの参加設定なしで登録し、メール確認後に自分のProjectを作成できます。

公開登録が成功すると、メールアドレスを持つ有効な全体管理者（`role=admin`、`status=active`）全員に通知メールを送ります。通知には登録者のユーザーID、未確認のメールアドレス、状態を記載し、確認用トークンやパスワードは含めません。管理者にメールアドレスがなければ通知先にはなりません。通知失敗はサーバーログへ記録し、登録と本人宛確認メールの結果には影響させません。管理者によるユーザー招待や確認メール再送は通知対象外です。

本番では `auth.email_verification=true` とし、`auth.verification_url` を公開 HTTPS の `/verify-email.html` に設定してください。PHP の `mail()` が実際に配送できることと、送信元アドレスの設定を実メールで確認してください。

登録画面は参加Projectの名前と投稿・編集の目的、共通アカウントの提供元、Open Across Baseの運営情報を表示します。戻り先はProject設定の`frontend_url`を使います。URL未設定の場合はリンクが表示されません。プライバシーポリシーは`privacy.html`、問い合わせ先は`info@openacrossbase.net`です。投稿内容・ユーザーIDの公開と、退会後も公開済みデータが残ることを登録前に確認できます。

## 本人によるアカウント削除

一般の投稿者も`account.html`から削除できます。現在のユーザーIDまたはメールアドレス・パスワードと、確認用の正確なユーザーIDを入力します。メール確認前の登録も削除できます。すべてのProjectの参加権限を失い、認証情報を削除します。投稿・Projectは保持し、本人との紐付けを解除します。最後の有効な管理者は先に別の有効な管理者を追加する必要があります。

削除処理は、本人に関係する管理監査ログとユーザーID・メール由来のRate Limit記録も削除します。サーバーやメールのログ、バックアップ、第三者が取得済みのコピーはこのAPIの削除対象ではありません。バックアップ復元時は削除済みアカウントを再び有効にしない運用が必要です。ログ・バックアップの固定保存期間や未認証登録の自動削除は今回の実装には含めず、プライバシーポリシーでも30日・90日等の未実施の期限を約束していません。公開データの利用ライセンスは各Project側で明示してください。

## プロジェクトの共同管理者

プロジェクト一覧の「管理者」から、登録済みのユーザーIDを指定して管理者を追加できます。操作できるのは、そのProjectの`project_admin`または全体管理者です。複数の管理者を設定でき、追加した管理者も同じProjectの設定・データ・管理者を管理できます。追加対象は有効な`user`または`admin`アカウントです。メール確認前・停止中のユーザーは追加できません。

管理者の追加で全体のアカウント権限や他Projectの割り当ては変更しません。解除すると対象Projectの`editor`となり、データ編集は継続できます。作成者の管理者権限、および最後の有効なProject管理者は解除できません。Projectの削除権限は従来どおり作成者本人または全体管理者に限ります。変更は監査ログへ記録します。構成ファイルだけで定義されたProjectでは、先にProject設定を保存してDB管理へ移行してください。

### プロジェクトへの参加禁止

全体管理者は「全ユーザー管理 → 詳細 → 利用プロジェクト」で対象プロジェクトをチェックし、権限を「参加禁止」にして保存できます。参加済みの場合も投稿・管理権限を失い、自分で再参加できなくなります。他のプロジェクトや既存の投稿は変更しません。権限を変更して保存するとその権限で復帰し、チェックを外して保存すると未参加状態に戻り、募集中なら再参加できます。全体管理者は対象外です。プロジェクト管理者の追加操作では参加禁止を解除できません。DBスキーマの変更は不要です。

### プロジェクト専用のユーザー管理と全ユーザー管理

プロジェクト詳細からの「ユーザー管理」（`admin/?view=users&app=...`）は、指定プロジェクトの参加者・参加禁止ユーザーだけを表示します。全体管理者と、そのプロジェクトの `project_admin` が参加権限の変更、参加禁止・解除、参加解除を操作できます。他プロジェクトの参加状況やメール・パスワード・アカウント権限は表示・変更しません。作成者の管理権限、最後の有効なプロジェクト管理者は削除・降格できません。全体管理者の参加権限はこの画面では変更できません。

全体管理者（アカウント権限 `admin`）には、共通ヘッダーに「全ユーザー管理」（`admin/?view=all-users`）を表示します。ここで従来のアカウント管理・ユーザー追加・パスワード再設定などを行います。パンくずは「ポータル › 全ユーザー管理」となり、特定プロジェクトには属しません。APIも `api/project-users.php` と、全体管理者専用の `api/admin-users.php` に分けています。

### マイページ

ログイン後の共通ヘッダー「マイページ」から `mypage.html` を開けます。本人が参加しているプロジェクトを、権限とともに25件ずつ表示します。非公開・停止中のプロジェクトも参加中であれば対象です。参加解除では本人の参加権限だけを削除し、投稿データと他のユーザーの参加状況は残します。参加禁止の記録や削除済みのプロジェクトは一覧に含めず、参加禁止を本人が解除することもできません。作成者と最後の有効なプロジェクト管理者は参加解除できず、その理由を表示します。未ログイン時はログインへの入口を表示し、ログイン後はマイページに戻ります。

プロジェクト詳細にも本人の「参加を解除」を表示します。募集中でない場合も利用でき、マイページと同じ解除API・権限保護を使います。ポータルの詳細では解除後に操作権限を再取得し、管理画面側の詳細から解除した場合はマイページへ移動します。

### 表示言語

共通ヘッダーの「言語 / Language」メニューで日本語・英語を切り替えます。判定は、有効な `?lang=ja` / `?lang=en`、`/ja/` / `/en/` ディレクトリ、ブラウザの優先言語の順です。ブラウザに日本語・英語の指定がなければ英語を使います。画面を移動する際は言語引数を引き継ぎます。URLの他の引数（`app`, `view`, `app_key` 等）とハッシュも維持します。保存操作や認証APIのURL、設定済みの外部マップURLは変更しません。

例: `/?lang=en`、`/?app=playgrounds&lang=ja`、`/en/`、`/ja/`、`/en/mypage.php`。管理画面は `/admin/?lang=ja`、`/en/admin/` を利用でき、ブラウザ設定や `lang` が異なる場合は該当する既存の言語版へ移動します。日本語ディレクトリの管理画面入口は `/ja/admin/` です。言語切り替え時にも管理画面の未保存変更の確認を行います。

ポータル、マイページ、登録、確認、再設定、アカウント削除、プライバシーポリシーの共通文言は `site-messages.js` にまとめています。管理画面は従来の `admin/ja.json`, `admin/en.json` を利用します。プロジェクト名や投稿内容など利用者が入力したデータは翻訳しません。ディレクトリ入口は薄いPHPファイルで共通HTMLを読み込み、公開画面の本文を複製しません。

### 管理者によるユーザーの削除

全体管理者（アカウント権限 `admin`）は「全ユーザー管理 → 詳細 → ユーザーを削除」で対象ユーザーIDを入力し、削除できます。プロジェクト配下のユーザー管理にはこの操作を表示しません。APIでも全体管理者の権限を確認します。自分自身と最後の有効な全体管理者は対象外です。

論理削除は既存の `users.status` を `deleted` に変更し、確認・再設定トークンを無効化します。既存セッションとパスワードでのログイン、プロジェクト操作は拒否されます。アカウント情報・投稿・所有プロジェクト・参加記録は保持し、通常のユーザー一覧とプロジェクト側の一覧からは除外します。全ユーザー管理の下部にある「削除済みユーザー」を開くと、別の表で記録を参照できます。表は初期状態では閉じており、開いた時に25件ずつ取得します。削除済みの記録は読み取り専用で、通常の状態変更・パスワード再設定等からの復活はできません。論理削除済みユーザーは本人向けの物理削除操作でも記録を消せません。既存の `status` 列を利用するためDBマイグレーションは不要です。

操作と監査ログ `user.soft_delete` は同一トランザクションで確定します。失敗時は状態変更とトークンの無効化を取り消します。既存ユーザーを自動的に論理削除する処理はありません。


削除済みユーザーの表では、全体管理者が「復活」「完全削除」を実行できます。どちらも対象のユーザーIDを正確に入力して確定します。「復活」は監査ログに残った削除前の状態（active / pending / disabled）へ戻し、パスワード・権限・参加記録を保持します。削除履歴がない場合、メール未確認ならpending、それ以外はactiveに戻します。古いセッションや確認・再設定リンクは復活させません。pendingの場合は必要に応じて確認メールを再送してください。管理画面のセッションはアカウント更新時に無効化されます。

「完全削除」は削除済みアカウントだけが対象です。アカウント・参加記録・トークン・識別情報を含む過去の監査ログとレート制限キーを削除します。投稿・プロジェクトは残し、そのユーザーへの作成者・更新者の参照を解除します。新しい監査イベントuser.purgeには対象の数値IDだけを記録します。全処理はトランザクションで確定し、失敗時は取り消します。復活・完全削除はプロジェクト単位のユーザー管理には表示しません。DBマイグレーションは不要です。


### カラム定義の環境間移行

画面名・パンくず・プロジェクト詳細のリンクは「プロジェクト設定」です。その中の「カラム定義」から「JSONをエクスポート」で、編集中の定義を保存前でも出力できます。本番環境の対象プロジェクトで「JSONをインポート」を押し、追加・削除カラムを確認して「カラム定義を読み込む」を選びます。表を確認し「設定を保存」で反映してください。読み込みだけではDBは更新しません。既存の定義は全体を置き換えます。カラムを定義から外しても投稿データは削除されません。

ファイルはformat=community-mapmaker-columns、version=1、schema.fieldsを持つJSONです。定義にはfield名、表示名、型、必須、並び順、選択肢、最大長、管理画面の表示・編集・幅を含みます。プロジェクト名・KEY・URL・公開状態・募集状態・ユーザー権限・投稿データは含めません。裸のfieldsオブジェクトを持つJSONも読み込めます。読み込み時と出力時に保存と共通のサーバー検証を行います。操作権限は設定の保存と同じです。

エクスポートにはシステム定義のid・osmidも含みます。インポート時はシステム定義と全項目が一致することを確認してから除外するため、追加・削除カラムの件数や保存対象には含めません。型・必須・表示名・管理画面設定などが異なる場合や、不足・余分な項目がある場合は、対象カラム名を示してエラーにします。JSONのキーの並び順は問いません。id・osmidを含まない従来のファイルも読み込めます。

### CSV取り込み時の座標補完

CSVのlatitude・longitudeが両方空欄、または両方の列がない場合、OSMIDから座標を補完します。CSVに入力済みの座標は保持します。OSMIDが同じ既存投稿に座標が保存されていれば、その値を使います。片方だけ空欄の場合は、両方入力または両方空欄にしてください。

nodeはその座標、way・relationは範囲の中心をOverpassから取得します。Overpassが失敗または未取得の場合は、残り時間内でOSM公式APIに切り替えます。nodeは最大100 IDずつ、way・relationは構成要素を取得して範囲の中心を求めます。欠けた構成要素がある場合は補完しません。`activity.coordinate_lookup.osm_api_fallback=false`でこの代替照会を無効化できます。Overpassは500 IDずつまとめ、同じIDは重複照会せず、既定24時間のキャッシュで確認・実行間の再取得を減らします。1リクエストの照会時間は全体で既定20秒までです。取得先はactivity.coordinate_lookup.endpoint（CMM_OVERPASS_URL）、キャッシュの保存先・保持時間・時間予算も同設定で変更できます。キャッシュ先はWebサーバーが書き込める非公開ディレクトリを指定してください。PHP cURL拡張を使います。

確認画面には補完件数・既存座標の保持件数・取得できない行のCSV行番号とOSMIDを表示します。取得できないまま続行するとその行は座標なしで取り込み、実行後も警告を表示します。OSMIDを変更した行では以前のOSMIDの座標を流用しません。外部への照会はDBトランザクション開始前に行い、確認操作だけでは投稿を書き換えません。通常の投稿・JSON取り込みの座標仕様は変更しません。

### 投稿データをまとめて削除する

投稿データ管理の操作欄は、プロジェクト・検索、行の編集、取り込み・出力、一括削除に分けています。全体管理者または対象プロジェクトの管理者には「すべての投稿を削除」を表示します。未保存の投稿編集がある場合は、保存または破棄してから操作してください。

対象件数はサーバーで取得し、表示中のページ・検索条件・読み込み済み件数に関係なく、そのプロジェクトの有効な全投稿を対象にします。確認画面でプロジェクトKEYを正確に入力して確定します。確認後に新規作成された投稿は対象外で、対象件数が変わった場合は再確認が必要です。投稿内容は保持し、通常の一覧・マップから非表示にします。既に削除済みの投稿、他プロジェクトの投稿、プロジェクト設定・カラム定義・参加ユーザーは変更しません。処理と監査ログは同一トランザクションで確定します。
